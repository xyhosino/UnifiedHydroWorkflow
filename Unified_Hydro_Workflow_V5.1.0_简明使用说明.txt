Unified Hydro Workflow V5.1.0
简明使用说明
============================================================

一、软件用途
------------------------------------------------------------
Unified Hydro Workflow 是原水文模型的辅助工作流程序，用于完成：

- GIS 数据预处理
- 计算单元扫描与管理
- SHP、站点、降雨、上游水源数据映射
- 计算前预检
- 多计算单元批量计算
- 运行失败时的 project.db 回滚保护

本程序不包含原水文模型程序、模型 DLL、数据库或实际业务数据。


二、启动程序
------------------------------------------------------------
运行：

UnifiedHydroWorkflow\UnifiedHydroLauncher.exe

程序启动后会自动检查模型环境。
顶部“模型环境”和“运行环境”显示正常后即可继续。


三、推荐使用流程
------------------------------------------------------------
1. 选择“计算单元根目录”。
2. 点击“扫描单元”。
3. 使用“智能映射（推荐）”。
4. 必要时点击“输入数据映射...”检查或手动指定数据。
5. 设置工程名称。
6. 设置场次开始、场次结束、上游水源开始时间。
7. 设置计算时间间隔。
8. 先将运行模式选择为“仅预检”。
9. 确认全部计算单元通过预检。
10. 不修改关键输入和参数，切换到“计算”正式运行。


四、数据预处理
------------------------------------------------------------
点击“数据预处理...”可以生成各计算单元需要的模型输入数据。

支持：
- ArcGIS Pro
- ArcGIS Desktop / ArcMap
- QGIS 3.x

需要准备：
- 流域 shp
- 河道 shp
- 节点 shp
- 土地利用 shp
- 土壤地质 shp
- 输出根目录

一般建议使用“自动检测（推荐）”。


五、计算单元输入数据
------------------------------------------------------------
每个计算单元通常需要 5 类 SHP：

1. 流域
2. 河道
3. 节点
4. 土地利用
5. 土壤类型

SHP 文件名不要求固定，只要程序能够正确识别，或在“输入数据映射...”中手动指定即可。

注意：不要随意修改 SHP 内部字段结构。
当前明确使用的关键字段包括：

流域：WSCU_Name、WSCD
河道：RVCD、FRVCD、RVCS
节点：NDCD
土地利用：XDMDM
土壤类型：TRZDBM


六、站点、降雨和上游水源
------------------------------------------------------------
站点和降雨数据可以放在计算单元目录，也可以使用外部数据目录。
本地数据优先。

如果自动识别错误，可在“输入数据映射...”中手动指定。

程序会根据河道拓扑判断是否需要上游水源。
需要时可使用：
- 计算单元目录中的已有水源表
- 外部上游水源目录中的文件
- 程序自动生成的水源表

正式洪水复盘时，如有可靠实测或上游模型结果，建议优先使用真实数据。


七、预检
------------------------------------------------------------
正式计算前建议先运行“仅预检”。

预检主要检查：
- 5 类 SHP
- 站点数据
- 降雨数据
- 上游水源需求
- 土地利用覆盖率
- 土壤覆盖率
- 输入映射状态

预检通过后，如没有修改关键输入或计算参数，再运行“计算”时会复用已通过的预检结果。


八、计算状态与结果
------------------------------------------------------------
运行时可在“计算单元状态”中查看：
- 5 类 SHP
- 站点
- 降雨
- 上游水源
- 覆盖率
- 状态
- 说明

覆盖率示例：
L 99.98% / S 99.98%

L = 土地利用覆盖率
S = 土壤覆盖率

计算结果通常位于原模型：
SKBYEXE\output\

每个计算单元完成后可重点检查：
out\outlet.csv


九、停止按钮
------------------------------------------------------------
当前版本中，“停止”会立即终止当前 Workflow 进程。
正在计算的单元可能无法完整完成。

因此除非确实需要中断，否则不建议在正常计算过程中使用“停止”。
计算失败或异常终止后，程序会尝试自动恢复 project.db。


十、帮助菜单
------------------------------------------------------------
主窗口顶部“帮助”菜单提供：

- 使用说明：在程序内查看本说明
- 运行诊断：生成完整诊断报告，可复制诊断信息并重新诊断
- 检查更新：通过 GitHub Releases 检查是否存在较新的正式版本
- 关于：查看当前版本、Workflow Core 版本和 GitHub 仓库地址

“运行诊断”会在原有运行环境检查基础上补充：
程序版本、部署模式、模型根目录、Workflow Core 文件状态、
GIS 检测结果与自动选择、Workflow Core capabilities 等信息。
GIS 自动检测优先级固定为：ArcGIS Pro → ArcMap → QGIS。
ArcMap 支持标准 Python27 目录以及 Apps\Development\ArcGIS*_envs 形式的自定义环境。

“检查更新”只比较 GitHub Release 版本，不会自动下载或覆盖现有程序。
无 Release、GitHub API 访问限制和普通网络失败会分别提示。
如果 GitHub 仓库尚未发布 Release，会给出相应提示。

GitHub：
https://github.com/xyhosino/UnifiedHydroWorkflow


十一、常见问题
------------------------------------------------------------
1. SHP、站点或降雨没有识别出来
   → 打开“输入数据映射...”手动指定。

2. 预检不通过
   → 查看状态表中的“状态”和“说明”。

3. 计算失败
   → 查看“运行日志”最后的 ERROR / FAILED 信息。

4. 环境异常
   → 先点击主界面“查看详情”；如需完整排障信息，使用“帮助 → 运行诊断”并复制诊断信息。

5. 修改了输入文件后是否需要重新预检
   → 需要。程序会根据关键输入和文件变化自动判断预检缓存是否失效。
